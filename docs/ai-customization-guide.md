# AI와 함께 내 오피스를 확장하기

ChatGPT·Claude·Codex에 전달할 수 있는 작업 가이드입니다. 이 문서는 실제 AI 업무 실행이나 외부 계정을 연결하지 않습니다. 코드를 바꾸는 도구와 앱 안에서 일하는 AI 직원은 별개입니다.

## 1. 수정 전 준비

1. 같은 주소 **127.0.0.1:3003**에서 개인 자료를 확인합니다.
2. 설정 → 데이터 연결 → **개인 백업** → 전체 개인 백업을 다운로드합니다. 소스 폴더 밖 비공개 위치에 보관합니다.
3. 소스 폴더도 복사해 수정 전 버전을 보관합니다. Git을 이미 쓰는 경우 현재 변경을 확인하고 본인 작업을 보존합니다. 미커밋 파일을 임의로 되돌리라고 요청하지 마세요.
4. 현재 이름·매출 합계·대표 건물·직원을 기록하되 이 개인 기록을 AI에 보낼 필요는 없습니다.
5. 한 번에 한 기능을 선택하고 성공 기준을 정합니다.

새 소스 버전이 나와도 localStorage를 초기화하거나 새 기본값으로 덮어쓰면 안 됩니다. 복구할 때 소스 버전과 브라우저 백업을 구분하세요. 다른 주소·포트로 실행하면 기존 자료가 안 보일 수 있습니다.

## 2. 코드 전달 방법

### 채팅 도구

처음에는 README.md, AGENTS.md, package.json과 관련 파일 몇 개만 제공합니다. 첨부가 지원되면 파일을, 지원되지 않으면 경로와 함께 작은 코드 조각을 보냅니다. ZIP을 무조건 모두 읽었다고 가정하지 마세요. UI 문제는 개인정보를 가린 화면과 재현 순서도 제공합니다.

ChatGPT 파일 활용은 [공식 안내](https://learn.chatgpt.com/docs/use-chatgpt)를 참고합니다. 계정·제품별 지원 범위를 확인하고, API Files 기능과 ChatGPT 화면 파일 첨부를 동일한 것으로 설명하지 마세요.

### 로컬 코딩 도구

프로젝트 폴더만 엽니다. 먼저 README와 AGENTS.md를 읽고 작업 범위·보호 대상·검증을 요약해 달라고 요청합니다. Codex는 프로젝트 AGENTS.md 지침을 읽습니다. [공식 지침 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Claude Code를 사용해도 README·AGENTS.md를 명시적으로 읽도록 요청합니다. 도구별 지속 지침은 공식 설명을 확인합니다. 여기서는 Claude/Codex 설치나 로그인·과금·API 키를 자동 구성하지 않습니다. [Claude Code 공식 개요](https://code.claude.com/docs/en/overview).

README는 실행·기능 설명이고 AGENTS.md는 코드 변경 시 지킬 경계입니다. 두 문서를 읽었다는 사실만으로 결과가 맞는 것은 아니므로 실제 테스트를 확인합니다.

## 3. 보내면 안 되는 것

실제 .env.local 등 환경 파일, 인증 파일, API 키·DB 접속 정보·Webhook, 개인 전체 백업, 실제 매출 CSV, 고객/계정 식별자, 브라우저 프로필, 실운영 로그, .git 이력은 제외합니다. node_modules와 .next*도 보내지 않습니다. 참고 프로젝트가 있는 docs/references는 배포 ZIP에서 제외되어 있습니다.

공유용 예시는 120000원 같은 가상 숫자와 가상 사업 ID를 사용합니다. 원본 회사 데이터나 저장 ID를 직접 일괄 치환하지 마세요. 소스의 .gitignore나 민감 패턴 검사만으로 모든 비밀정보가 제거됐다고 믿지 말고 보내는 파일을 확인합니다.

## 4. 모든 요청 앞에 붙일 공통 지침

```text
현재 프로젝트 안에서만 변경해 주세요. README.md와 AGENTS.md를 먼저 읽어 주세요.
기존 3D 씬·카메라·캐릭터 외형·라우팅·자동화 발굴실을 보호해 주세요.
표시 이름과 고유 ID를 분리하고 기존 저장 키/버전과 사용자 데이터를 초기화하지 마세요.
DEMO 원장은 유지하고 개인 수동/CSV와 합산하지 마세요.
실제 API 키·인증 파일·개인 백업은 읽거나 요구하지 마세요.
새 패키지·DB 변경·서버 연결·라이선스 변경은 필요성을 보고하고 먼저 승인받으세요.
실제 배포·GitHub 공개·Notion 게시·외부 업무 실행은 하지 마세요.
변경 파일, 이유, 테스트 명령과 실제 결과, 남은 한계를 보고해 주세요.
실패 테스트를 삭제하거나 skip해서 통과시키지 마세요.
```

## 5. 건물 추가 요청 예시

단순히 이름을 바꾸는 경우는 코드 수정 없이 설정 → 도시·건물을 사용합니다. 빈 부지에 기존 유형을 등록할 때는 도시의 건물 등록 기능을 먼저 사용합니다. 새로운 모델·부지를 개발하려면:

```text
기존 5종 모델을 유지하면서 새 사업 유형의 건물 모델 하나를 추가해 주세요.
Three.js Geometry/Material로 기존 파스텔 스타일과 원근을 맞춰 주세요.
기존 assetId/plotId를 변경하거나 부지를 덮어쓰지 마세요.
먼저 lib/three-world/model.ts, 건물 컴포넌트, 설정 검증과 등록 흐름을 확인해 주세요.
새 유형의 3D 선택·공사 단계·담당 자산 매핑·내부 입장 정책을 함께 설계해 주세요.
수익이 없는 새 건물에 임의 매출을 만들지 마세요.
등록·새로고침·선택·CSV 건물 매핑·기존 모델 회귀를 브라우저에서 검사해 주세요.
```

현재 12개 부지를 넘기려면 좌표·클릭 영역·카메라·빈 부지 검증도 함께 확장해야 합니다.

## 6. 직원 추가 요청 예시

이름·역할·색상은 설정 → 직원에서 먼저 바꿉니다. 새로운 ID를 가진 직원을 추가하려면:

```text
기존 새싹 캐릭터 Geometry와 애니메이션을 재사용해 신규 직원 한 명을 추가해 주세요.
현재 직원 ID와 이동 경로, 책상 배치를 바꾸지 마세요.
설정 기본값/유효성 검사/옛 설정 마이그레이션/사무실 좌석/선택 카드까지 점검해 주세요.
사용자가 표시/활성 상태와 부서·색상을 바꿀 수 있어야 합니다.
실제 AI 미연결인 개인 모드에서는 업무 미연결로 표시하고 가상 업무를 실제 실행처럼 표현하지 마세요.
기존 설정을 새 기본값으로 덮어쓰지 말고 새 프로필만 안전하게 추가하는 방식을 제안해 주세요.
```

직원 배열 길이만 늘리면 실내 경로·배치·검증이 깨질 수 있습니다. 모델 선택/API 키를 브라우저 프로필에 넣지 않게 하세요.

## 7. 수익 대시보드 수정 요청 예시

```text
금고에 매출/환불/광고 추정수익의 기간 비교를 추가해 주세요.
lib/operations/model.ts의 공통 재무 의미와 기존 집계 함수를 재사용해 주세요.
순매출/순이익은 원천 입력값과 구분하고 지급액을 수익에 다시 더하지 마세요.
비용·비교일·환율이 없으면 산정 불가/자료 없음으로 표시해 주세요.
체험 원장 숫자와 개인 CSV를 혼합하지 마세요.
모드 전환·0원/미입력·통화별 조회·CSV 교체·직원 보고 동기화를 테스트해 주세요.
건물·회사·직원 이름 변경 후에도 데이터 ID 매핑이 유지되어야 합니다.
```

## 8. 외부 API 연결 요청 예시

이 요청은 설계부터 시작합니다. 실제 운영 서비스에 대한 포괄 실행 허가가 아닙니다.

```text
현재 수동/CSV 재무 형식에 맞는 서버 전용 읽기 어댑터 설계를 먼저 작성해 주세요.
운영 n8n·DB를 직접 실행/수정하지 말고 필요한 계약·권한·원천 필드만 정리해 주세요.
원천 → 주기 수집 → 인증된 서버 수집 계층 → Workspace 격리 저장소
→ 권한 검증 API/Provider → 기존 공통 집계/대시보드 구조로 설계해 주세요.
외부 서버가 브라우저 localStorage에 직접 쓴다고 가정하지 마세요.
비밀값은 서버에서만 처리하고 NEXT_PUBLIC/localStorage/설정 JSON에 넣지 마세요.
공개 DEMO에서 실데이터 접근을 허용하지 마세요.
idempotency 키, 기준일/통화, 갱신 시각, 실패/지연, 읽기 전용 권한과 비용 한도를 명시해 주세요.
실제 연결·패키지 설치·DB 스키마 변경·배포는 구체적인 변경안을 검토한 뒤 별도 승인받으세요.
```

CSV 한 번 가져오기는 자동 연동이 아닙니다. 자동 기능이 구현되고 테스트되기 전까지 추가 개발 필요로 표시합니다.

## 9. 수정 후 검사와 되돌리기

Mac:

```sh
npm test
npm run typecheck
npm run build:local
```

Windows에서는 `npm.cmd`를 사용합니다(Windows 실기 미검증). 브라우저 검사가 필요하면 `npm run test:template -- --workers=1` 및 관련 기존 Playwright 스위트를 실행합니다. 브라우저 설치·실행법은 README를 따릅니다.

검증 화면: 새 회사와 기존 회사, /city, 건물 내부, /finance, /settings/data, /automation-lab. 체험 원장 총매출이 유지되는지, 개인 CSV가 해당 건물에만 반영되는지, 새로고침 후 자료가 유지되는지 비교합니다. 테스트 합격이라는 답만 받지 말고 명령·결과·스크린샷을 요청하세요.

오류가 나면 추가 수정 전에 멈추고 실패 원인과 영향 범위를 정리합니다. 수정 전 코드 복사본을 되돌릴 때도 브라우저 자료는 자동 초기화하지 않습니다. 자료를 복원할 필요가 있을 때만 개인 백업 복원을 사용하며, 새 형식을 오래된 코드가 못 읽을 수 있으므로 백업 버전·코드 호환성을 확인합니다. 호환되지 않는 파일을 억지로 강제 가져오지 마세요.

## 10. 공개하기 전에

개인 버전이 잘 작동해도 공개 배포는 별도입니다. 자신의 코드 라이선스 선택·저작권 표기·이미지 권리·의존성 고지를 확인하고, 검토 ZIP이 실제로 개인 자료를 제외하는지 검사합니다. AI에게 LICENSE를 마음대로 정하거나 인터넷에 바로 올리라고 요청하지 마세요. 외부 게시와 운영 시스템 연결은 소유자가 각각 승인해야 합니다.
